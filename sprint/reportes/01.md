## El hueco de «4 archivos, 2 llamadas»

### Causa encontrada

En `CargarTarifario.tsx`, el `onChange` del file input llamaba `elegir(f)` **sin await**:

```tsx
onChange={e => {
  const f = e.target.files?.[0];
  if (f) elegir(f);    // ← promesa no awaiteada
  e.target.value = '';
}}
```

Y `elegir` tenía `await buscarDuplicado(file)` **sin try/catch**. Si `hashArchivo()` fallaba (archivo no legible, error de crypto, memoria), la promesa se rechazaba sin handler. El botón volvía a la normalidad y el archivo desaparecía sin mensaje.

`procesar()` SÍ tenía su try/catch, pero `elegir()` fallaba ANTES de llegar ahí.

### Fix

Envolví la llamada a `buscarDuplicado` en try/catch dentro de `elegir()`. El error ahora se muestra en el mismo panel de errores que los demás (`setError`).

### Escenarios descartados

- **El input no tiene `multiple`**: el file picker nativo solo deja elegir un archivo a la vez. No es posible seleccionar 4 de golpe.
- **Storage o Firestore fallan en silencio**: no. `uploadBytes` y `setDoc` (vía `conAviso`) están dentro del try/catch de `subirDocumento`, que rethrow hasta `procesar`, que sí atrapa y muestra.
- **Race condition por `subiendo`**: teóricamente posible (el flag se pone dentro de `subirDocumento`, no en `elegir`), pero el file picker es un modal nativo que bloquea la interacción. No es la causa de 4 archivos.

### Escenario más probable

Gaby abrió el diálogo cuatro veces consecutivas. Dos pasaron bien. Dos fallaron en `buscarDuplicado` (hashArchivo) y la promesa se rechazó sin que ella viera nada — pensó que se habían subido.

## Hallazgos fuera de la tarea

1. **El `accept` del file input en `CargarTarifario.tsx` no incluye `.txt` ni `.eml`**, pero el de `EvidenciasTarifas.tsx` sí. No lo toqué: la vía correcta para correos es "Pegar correo", y agregarlos al file picker dejaría subir archivos que n8n no sabe leer.

2. **`medirTarifarioCargado('exito', 0)` se llama cuando n8n contesta `ok: false`** — es incorrecto para analítica pero no afecta al usuario. No lo toqué.

3. **El año de la vigencia se asume 2024** porque el correo solo dice "July 31". n8n no puede saber el año. La pantalla de revisión lo deja editable.
