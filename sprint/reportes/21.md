## Decisiones que tomé y cómo se revierten

1. **Toda la gestión pasa por la Function, no por acceso directo a Firestore.**
   `usuarios/{uid}` no tiene regla en `firestore.rules` (no se puede editar).
   El Admin SDK bypasea las reglas. El cliente llama a la Function para listar,
   invitar, cambiar y desactivar. Se revierte quitando la Function y poniendo
   un hook con acceso directo cuando se desplieguen las reglas de `usuarios`.

2. **Refresco de claims con `visibilitychange` en vez de listener de Firestore.**
   Sin regla para `usuarios/{uid}`, el cliente no puede escuchar su documento.
   Al volver a la pestaña, AuthContext llama `getIdToken(true)` para refrescar
   claims. Es menos inmediato que un listener, pero funciona sin cambio de
   reglas. Se revierte agregando `onSnapshot` de `usuarios/{uid}` cuando se
   desplieguen las reglas.

3. **`usuario.gestionar` solo para `admin`, no para `administracion`.**
   Gestionar las cuentas del sistema es soporte técnico, no función del negocio.
   Si Vermur decide que Administración también invite, se agrega la capacidad.

## Hallazgos fuera de la tarea

1. **La siembra automática (seedGuard) se rompe con reglas por rol.** Lo documenta
   el borrador de reglas. Solución: mover la siembra a una Function o a un script
   con Admin SDK. No es urgente: solo afecta emuladores.

2. **`sembrarEmuladores.sh` no pone claims.** Al migrar a claims, las cuentas de
   prueba necesitan que el script también ponga el claim `rol` después de crearlas.
   Hoy funciona porque AuthContext cae al mapa viejo.

3. **`ordenCompra.solicitar` y `ordenCompra.gestionar` faltan en las capacidades del
   servidor** (`functions/src/comun/auth.ts`). No afecta nada porque ninguna Function
   las exige, pero el espejo está incompleto. No lo toqué por ser fuera de la tarea.

## Para publicar

- **Functions:** `gestionarUsuarios` es nueva. Desplegar con:
  ```bash
  npx firebase deploy --only functions:gestionarUsuarios
  ```
  Pero antes de desplegar, las cuentas del equipo necesitan custom claims. Orden:
  1. Desplegar la Function
  2. Que admin invite a cada miembro desde la pantalla (o un script con el Admin SDK)
  3. Verificar que todos entran con claims
  4. Desplegar las reglas por rol (borrador en `docs/reglas/`)
  5. Punto de regreso: si falla, revertir las reglas al parche de correos y desactivar
     la Function sin borrarla.
